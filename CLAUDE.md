# Q-RELAY — rules of engagement

Project: Qiskit Fall Fest 2026 (DBATU) hackathon. Full spec in `PROMPT.md`.
Python venv at `.venv` (Python 3.12, Qiskit 2.6.1). Windows: use `tasks.ps1` or `make` if available.

1. Correctness before beauty: never present unverified numbers. Every figure in the report is generated by code in `scripts/build_report_figures.py` from real runs.
2. No fabricated data. Label every result's source (SIM / EMU / HW).
3. Keep quantum logic in `qrelay/` and keep it free of web code; the server and UI only call into it.
4. Be explicit about qubit ordering (Qiskit is little-endian) in code comments wherever bits are parsed.
5. Prefer small, deterministic tests with fixed seeds; seeds are configurable and recorded.
6. Do not commit secrets, tokens, or `node_modules`. The IBM token is read only from `QISKIT_IBM_TOKEN` (and `QISKIT_IBM_INSTANCE`).
7. After each milestone: run the relevant tests, commit with a clear message, append decisions to `docs/DECISIONS.md`.
8. Keep the UI responsive: heavy computation is precomputed or done server-side; never block the render loop.
9. If a library API differs from the spec, check the installed version's docs/source, adapt, and log it. Do not guess.
10. When you finish a phase, print a 5-line status: done / tests passing / known issues / next phase.
